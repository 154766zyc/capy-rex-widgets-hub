# Rex Widgets Hub CF 3.5.1 → 3.6.0 更新内容

只写 Cloudflare 部署版。模块 / 合集 / 首页 ID、分享名、公开地址、备份格式（format 1–8）在这些版本之间都没有变；3.5.8 自动新增一张「文件」表，3.6.0 自动补 3 个索引、首页表加 3 个栏位。3.5.1 起的任何版本都可以直接覆盖升级到 3.6.0，数据保留（`wrangler.toml` 的 `name` 不要改）。

---

## 3.5.1：第一版 Cloudflare 部署版

- 数据改存在 SQLite 型 Durable Object 里，不再使用 KV + D1，`wrangler.toml` 不用填任何编号。
- 恢复备份、覆盖模块、批量写入中途出错时整体撤回，不会只写一半。
- 超过 2 MB 的文件自动分片存储，读出来是原文件；没有引用的分片每 6 小时清理一次。
- 「全部同步」由 Durable Object 闹钟约每秒续跑，关掉页面也会继续；中途被回收，重启后从中断处继续，不重复、不遗漏。
- 每 5 分钟一次的定时任务：订阅检查、自动分类、过期清理。
- PWA 图标随代码打包。
- 首页配置管理、ZIP64 首页包、format 8 备份。

## 3.5.2

- iPhone 上首页「复制分享链接」失败：已分享的直接复制，第一次分享点确认时就开始复制。
- 自动复制被浏览器拒绝时，弹出手动复制框显示完整链接，长按即可复制。
- 首页包和头像在同一行、加起来可能超过 2 MB 写不进去：超过 256 KB 的内容改为分片存储。
- 上传带文件大小时不再在内存里多复制一份。

## 3.5.3（优化版）

- 公开下载每次查数据库从 7 条 SQL 降到 3 条，不再全表扫描。
- 缓存读取（`getWithMetadata`）3 条 SQL 合并成 1 条。
- 备份导出、恢复少做重复查询。
- 标题扫描加了索引。

## 3.5.4：代码审查后的修复

- 链接模块自动刷新会被坏源卡死：失败的模块也记录检查时间，6 小时后才重试，其它模块照常轮到。
- 链接模块内容没变也每 6 小时整份重写，Rex 每次都重新下载：先比对 SHA-256，一样就不写入。
- 直链 `/<模块ID>.js` 不支持 304：改为和 `/api/modules/` 一致，支持 If-None-Match。
- 第一次登录后改 `ADMIN_PASSWORD` 机密无法重置密码：换成新机密即可登录重置；旧机密不会复活；旧会话全部退出。
- 旧恢复接口收到坏 JSON 报 500：改为 400，提示「备份文件不是有效的 JSON」。
- 恢复大备份会失败但事先没提示：选择超过 20 MB 的备份时提醒（只提醒，不拦截）。
- 自动分类规则匹配是 O(模块数 × 订阅条目数)：按模块预先分组、关键词缓存，结果不变。

## 3.5.5：条件请求

- 合集订阅每 6 小时把每个模块整份重新下载：记住上游的 ETag / Last-Modified，上游没变就回 304，不下载、不写入。
- 链接模块自动刷新同样改成条件请求；手动「刷新」仍然完整下载。
- 「全部同步」时每秒一次的闹钟都跑整套维护：每秒那次只推进同步队列，完整维护每分钟最多一次。

## 3.5.6：热点路径与内存

- Rex 拉订阅 `.rex`：只查这个合集里的模块并加了索引，每次读取的行数 4301 → 901（-79%），耗时约 20 ms → 10 ms；内容没变时回 304（约 5 ms）。
- 管理页模块列表（2000 模块）：约 75 ms → 42 ms。
- 导出备份改成边编码边输出，输出逐字节相同：导出 40 MB 备份峰值内存 287 MB → 146 MB；80 MB（含图标）440 MB → 196 MB。
- 图标回 304 或 HEAD 时不再读出整张图片。
- 新增 `single-file` 单文件部署：3 个文件、3 行命令；附部署 PDF。

## 3.5.7：首页包上传

1. **上传首页包报「首页 ZIP 解压失败或超过大小限制」**：Hub 原来用 Cloudflare 自带的 zlib 解压，Cloudflare 上的行为和本地不完全一样，正常的 Rex 导出包也传不上去。改用 Hub 自带的解压程序（`inflate.js`），任何环境结果一致，解压大小上限由 Hub 自己控制。
2. **首页包被误判「内容校验失败」**：Rex 导出包里常有校验值很大的文件，改用 Hub 自己的校验算法。
3. **出错看不出原因**：解压失败会附上出错的文件名和具体原因。
4. 不再依赖 `node:zlib`。
5. 两份图文教程 PDF（附真实界面截图）和部署说明 `CF-DEPLOY.md` 更新到 3.5.7。

**3.5.7 测试**：两轮完整测试，CF 模拟环境 263 项全部通过；自带解压与标准 zlib 用 2 万组随机数据逐字节一致，2 万组损坏数据无异常、无卡死；故意改坏 6 处关键代码，测试都能发现；用户反馈失败的 2.2 MB、128 KB 首页包上传成功、导出与原文件逐字节一致；3.5.6 的数据库直接升级到 3.5.7，模块、合集、首页、备份都完整。

## 3.5.8：新功能和省内存（2026-11-23）

1. **只同步失败的订阅**：「全部同步」旁边新增「只同步失败（n）」。部分失败的合集只重下失败的模块，整个出错的来源完整同步一次。
2. **恢复备份两种方式**：「增量合并」（默认，保留现有数据）和「全量恢复」（先清空备份包含的部分再恢复，同一事务，失败整体回滚，需二次确认）。备份里模块的分享链接保持不变。
3. **替换模块时可以填版本号**：上传预览每一行都有「版本号（可选）」，手填优先。
4. **加密模块自动更新版本号**：内容变了就生成 `YYYY.MM.DD.N`（北京时间），同一天 N 加 1；代码或合集里写了版本号时以写的为准。
5. **上传模块可以选 `.zip`**：浏览器里解压，取出 `.js` 再预览；跳过 `__MACOSX`、隐藏文件和其它文件；GBK 中文文件名也能识别。
6. **首页支持 Forward `.fwd`**：自动转成 `.rex` 保存，栏目原样保留（未在 Rex 实测）。
7. **图标直接上传图片**：PNG / JPEG / WebP，最多 2 MiB。
8. **合集页「文件」栏目**：PDF / txt / zip，单个 25 MiB，总共 100 MiB、200 个；可分享、替换（链接不变）、改名、备注、删除；只按文件头判断类型，网页、SVG 不收。
9. **设置页显示存储用量**：已用 / 1 GB（免费计划），超过 80% 提醒。
10. **恢复备份大幅省内存**：边读边处理，模块文件读完一个就暂存一个。本地模拟存活内存峰值：28 MB 备份约 49 MB → 约 12 MB；60 MB 备份约 105 MB → 约 23 MB。
11. **订阅同步更快**：每轮 6 个模块（原来 2 个），同时下载仍是 2 个，请求次数约为原来的三分之一。
12. **只导出部分备份**：全部 / 只导出模块数据 / 只导出首页配置 / 只导出文件栏目。
13. 其它：链接模块自动刷新到加密模块时不再清空作者；「清除所有数据」也清空首页和文件；图文教程合成一份《图文指南》PDF（两个部分），多帐号改为「每个帐号一个文件夹 + 帐号档案」，`CF-DEPLOY.md` 同步更新到 3.5.8。

**3.5.8 测试**：一轮完整测试 + 工程级检查。普通环境 284 项、CF 模拟环境 284 项全部通过（新增 21 项）；流式解析 300 多组随机分块与 `JSON.parse` 一致；故意改坏 12 处发现 11 处（剩下 1 处是等价改动）；3.5.7 的数据库直接升级到 3.5.8 数据完整；真实 Chrome 走通 zip 上传和图标上传。仍未在真实 Cloudflare 帐号验证。


## 3.6.0：省 Cloudflare 用量 + HTML 首页卡片

**重点**

- **起因**：3.5.8 每 5 分钟的定时维护整表扫描；某站一次读约 18,099 行，一天约 520 万行，超过免费每天 500 万行。
- **维护走索引**：标题补扫、链接模块刷新、过期清理只读到期的那几行。
  - 1000 个模块：一次约 5,035 行 → 约 35 行。
  - 3000 个模块：一次约 47 行。
  - 一天：约 145 万行 → 约 1 万行。
- **自动分类**：没有新模块就跳过，最多 24 小时补扫一次。
- **图标清理**：最多 6 小时一次。
- **内存缓存**：公开合集（`.rex` / `.fwd` / JSON）、管理页模块 / 合集 / 分组列表，没改数据时 0 次查询；304、HEAD 也是；管理列表要登录。
- **删 0 行不算写入**：维护不再把内存缓存清空。
- **少写闹钟**：Cron 不再每 5 分钟重设；空闲最长睡 1 小时。
- **存储清理**：每张表只扫一遍（原来每列各扫一遍）。
- **静态文件**：图标、favicon、manifest、CORS 预检不进 Durable Object。
- **设置「自动更新」**：6 / 12 / 18 / 24 小时，默认 6，改了自动重排。
- **可选边缘缓存**：默认关；Rex 拉合集、下载模块不进 Durable Object；没在真实 Cloudflare 上测。
- **修正**：升级上来的站第一次打开也会补上新索引（测试中发现）。

**HTML 首页卡片（重点）**

- **HTML 首页卡片（适配 Rex 1.2）**：首页包 version 2、`rex-html/`、内联 `htmlTemplate` 都能上传；包内文件数 32 → 256。
- **检查首页**：卡片、尺寸声明、缺字段、本机模块、外站链接、模块对照一次看清；首页卡片上直接显示摘要。
- **首页工具**：换成 Hub 模块链接、装上 HTML 卡片（另存或覆盖）、取消分享 / 换新分享链接。
- **真实数据实测**：Rex 1.2.1 备份里 35 个首页、8 张 HTML 卡片全部能上传、没有误报。

**3.6.0 测试**

- 普通环境 300 项：299 通过，1 项环境跳过。
- CF 模拟环境 308 项：306 通过，2 项要直接改数据库文件、CF 版跳过。
- 维护查询经 EXPLAIN 检查，没有整表扫描。
- 故意改坏 6 处，全部发现。
- 3.5.8、3.5.9（HTML 卡片版）数据库升级到 3.6.0：数据完整，索引补上。
- 真实 Chrome 走通「自动更新」设置。
- 仍未在真实 Cloudflare 帐号验证。

## CF 的限制

| 限制 | 说明 |
|---|---|
| 单次上传 | 最多 100 MB（Cloudflare 免费版和 Pro 版的限制）；超过的备份请分开导出（模块数据 / 首页 / 文件） |
| 首页包 | 单个最多 25 MiB |
| 内存 128 MB | 3.5.8 起恢复备份边读边处理，模块文件一次只占一个；首页配置和文件栏目的内容仍要整段读进内存，很多时请分开导出、分别恢复；失败会整体撤回，现有数据不受影响 |
| CPU | 每次请求默认最多 30 秒；付费计划可打开 `wrangler.toml` 的 `[limits] cpu_ms`；实测 28 MB 备份恢复约 0.6 秒 |
| 单行 2 MB | 超过 256 KB 的文件自动分片存储，不影响使用 |
| 并发 | 按请求数计算，最多 64 个；不按内存算，同时多个大上传仍可能把内存撑满 |
| 订阅地址 | 只能用公网 HTTPS 地址，不能访问内网来源 |
| 条件请求 | 上游不给 ETag / Last-Modified 时，退回完整下载加内容比对 |
| 定时任务 | 每 5 分钟一次（过期清理、自动分类、订阅检查、链接模块刷新）；3.6.0 起每次只读几十行；订阅和链接模块按设置的间隔（默认 6 小时）检查 |
| Durable Object 免费额度 | 每天读 500 万行、写 10 万行（`setAlarm` 和删除都算写入）；3.6.0 的定时维护一天约 1～1.5 万行（3000 个模块以内）；主要用量是 Rex 拉合集和管理页打开模块列表（Durable Object 被回收或改过数据后的第一次） |
| 内存缓存 | 只在 Durable Object 没被回收时有效；改了任何数据都会失效 |
| 边缘缓存（可选，默认关） | 仍算 Worker 请求（免费每天 10 万次）；合集最多晚约 1 分钟、模块最多晚约 5 分钟更新；没在真实 Cloudflare 上测过 |
| 同步速度 | 每轮 6 个模块（同时下载 2 个），比 3.5.7 快约 2～3 倍，实际看上游下载速度 |
| 文件栏目 | 只收 PDF、txt（UTF-8）、zip；单个 25 MiB，总共 100 MiB、200 个 |
| 图标上传 | PNG / JPEG / WebP，单张 2 MiB；图标缓存总共 128 MiB |
| `.fwd` 转换 | 栏目原样保留；头像只保留 PNG；转换结果没在 Rex 实测 |
| 存储空间 | 免费计划每个 Hub 最多 1 GB（数据都在一个 Durable Object 里，Cloudflare 免费计划每个上限 1 GB，付费计划 10 GB）；满了以后写入会失败，读取不受影响；设置页「存储用量」可以看已用多少 |
| 首页检查 | 静态检查，不代表 Rex 原生渲染、导入或播放已通过；单张 HTML 最多 32,768 字节 |
| 一键导入首页到 Rex | 还没有；Rex 新版已支持用链接导入首页，Hub 还没接上，目前下载 `.rex` 后用 Rex 打开 |
