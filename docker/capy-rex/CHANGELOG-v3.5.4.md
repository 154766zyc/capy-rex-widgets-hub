# 3.5.4（2026-11-22，审查修复版）

以 3.5.3 为底，做了一轮工程审查后的修复版，**不是上游发布的 3.5.4**。模块、合集、首页 ID、分享名、公开地址和备份格式（format 1–8）都没变，可以直接覆盖 3.5.3 部署。数据库会自动加一列 `link_checked_at`，旧库在第一次启动时补上。

## 修正了 CF 什么

1. **链接模块自动刷新会被卡死（Bug）**
   每 5 分钟的定时任务一次只刷新最久没更新的 4 个链接模块。下载失败的模块不会更新时间，所以会一直排在最前面。只要有 4 个源坏了（失效、404、超时），其它链接模块就永远不会再自动更新。
   修正：每次检查前先记下检查时间，失败的模块也要等 6 小时才重试，其它模块照常轮到。

2. **内容没变也整份重写（优化）**
   以前每 6 小时，链接模块不管有没有变化都重写一遍：要整份写入 Durable Object，还会换掉 ETag，导致 Rex 每次都重新下载。
   修正：先比较 SHA-256，内容一样就只记录检查时间。这样写入次数变少，ETag 保持不变，Rex 可以直接拿 304。手动点「刷新」仍然强制重写。

3. **直链 `/<模块ID>.js` 不回 304（优化）**
   `/api/modules/…` 已经支持 `If-None-Match`，直链却没有，每次都传整份文件。现在两条路径一致；返回 304 时也会关闭没用到的读取流。

4. **忘记密码无法重置（Bug）**
   第一次登录后，密码会以哈希的形式存进数据库，之后在 Cloudflare 改 `ADMIN_PASSWORD` 机密完全不起作用。只用手机的话，忘记密码就没办法了。
   修正：在 Cloudflare 把机密换成新值，用新值登录即可重置，所有旧会话会被退出。只有机密真的换过（和上次记录的指纹不同）才生效，旧机密不会因此重新可用；在管理页改过的密码也不会被现有的机密盖掉。
   注意：从 3.5.3 升级上来后，要先用 3.5.4 正常登录一次，记下当前机密，之后改机密才能重置。

5. **旧恢复接口收到坏 JSON 时报 500（Bug）**
   `/api/admin/backup/restore` 收到无效 JSON 时，只返回看不懂的「Internal error」。现在返回 400 和「备份文件不是有效的 JSON」。

6. **大备份恢复前提醒（CF-1 的软缓解）**
   在 CF 上选择超过 20 MB 的备份时，界面会提醒：CF 内存只有 128 MB，可能恢复失败（失败会整体回滚，现有数据不受影响）。只提醒、不拦截，仍可继续恢复。

7. **自动分类规则匹配变快（优化）**
   以前每个模块都要扫一遍全部订阅条目（模块数 × 条目数），关键词也要每次重新拆分。现在订阅标题按模块预先分好、关键词缓存，匹配结果不变。2000 个模块的「预览/立即整理」可以少用很多 CPU 时间，更不容易碰到 CF 的 CPU 上限。

8. **文档**：CF-DEPLOY.md 写的是「密码至少 4 位」，但管理页改密码要求至少 8 位，现在统一成「建议至少 8 位」，并补上了忘记密码的重置方法。

## CF 的限制（这一版仍然存在）

- **单次上传最大 100 MB**（Cloudflare 免费版和 Pro 版的限制）。
- **内存 128 MB**：恢复时额外占用的内存约是备份大小的 3 倍。20 MB 以内比较稳妥，20–30 MB 可能失败，超过 30 MB 基本不行。现在会提醒，但不会拦截。
- **备份导出整份放在内存里**：图标缓存接近 128 MB 时，导出一定会失败（CF-4/CF-5）。
- **单次请求 CPU 默认 30 秒**（免费计划）：恢复大备份可能超时；付费计划可以打开 `wrangler.toml` 里的 `[limits] cpu_ms`。
- **单行 2 MB 上限**：超过 256 KB 的文件会自动分片，不影响使用。
- **不能访问内网来源**：订阅和链接只能用公网 HTTPS 地址。
- **订阅同步仍是全量重新下载**：合集条目没有存 ETag（CF-6）。单个模块的订阅已经支持条件请求。
- **定时任务每 5 分钟一次**：自动分类、六小时订阅检查和链接模块刷新都按这个节奏运行。
- **并发上限只按请求数计算（64），不按内存计算**：同时进行多个大上传仍可能把内存撑满（CF-2）。
- **以上 CF 结论都来自本地模拟（fake Durable Object），没有在真实的 Cloudflare 账号上验证过。** 首次部署建议用新的 Worker 名称，先打开 `/healthz`（应显示 `"version":"3.5.4"`），再用一份小备份试一次恢复。

## 审查过但这次没改

- 公开接口 `Access-Control-Allow-Origin: *`：只对公开下载有意义。管理接口用的是 `SameSite=Strict` 的 HttpOnly Cookie，跨站请求不会带上，不构成 CSRF 风险。
- 管理页里来自远端的标题、作者、文件名都经过 `esc()` 转义后才放进 innerHTML，没有发现 XSS。
- 登录限流放在 Durable Object 的内存里：CF 版只有一个实例，计数是准的；实例重启后计数会清零，这是可以接受的。
