# CF 3.5.2 验证记录（2026-11-21）

## 已验证

- **Docker 路径不受影响**：自动化测试 245 项，244 通过、1 项因环境没有内网网卡跳过、0 失败（Node 22.23）。
- **同一套 HTTP 测试跑在 CF 版上**（`npm run test:cf`）：229 项共用测试 + 15 项 CF 专属测试，共 244 项全部通过。跳过的 16 项是 Docker 专属功能，CF 上没有：关闭地址检查/Fake-IP、内网可信源、反向代理信任、`server.js` 的 gzip、磁盘升级快照、旧 Docker 数据库原位升级。
- **CF 专属测试**覆盖：
  - 返回 ≥400 或抛错时整体回滚，嵌套失败不影响外层，D1 批量写入全成或全不成，`changes` 计数正确。
  - 超过 2 MB 的值分片存储、读出原字节、相同内容只存一份、删除后分片被清理。
  - 同一行两个约 1 MB 的内容（首页包 + 头像）不超过 2 MB 行上限（改前这项会失败）。
  - 6 MB 首页包：上传、原字节导出、重启后仍在、format 8 备份、删除后清理、从备份恢复。
  - 恢复备份写入时可以查询进度，提交前不会显示完成。
  - 「全部同步」后约 1 秒内唤醒；没有订阅时睡满 15 分钟，不会频繁唤醒。
  - Cron 和闹钟维护任务都能正常运行。
  - 未登录的大上传在读取前拒绝，超限返回 413。
  - 登录、加密模块源码保护、拒绝导入内网地址、ETag 304、删除后 404。
- **CF 专项测试（第二批）**：
  - 「全部同步」不开页面、只靠闹钟跑完 40 个模块：21 轮完成，每个模块只下载一次，完成后闹钟回到空闲间隔。
  - 同步跑到一半 Durable Object 被回收（模拟重启）：重启后继续，30 个模块全部更新，总共下载 30 次，没有重复、没有遗漏。
  - Docker → CF → Docker 备份互通：3 MB 加密模块字节、模块 ID、合集、1.5 MB 首页包和头像全部一致（format 8）。
  - 并发：30 个公开下载、5 个上传和 5 个列表请求同时进行，全部成功，没有卡死。
  - 大备份（Node 估算，不是 Cloudflare 实测）：

    | 备份大小 | 恢复耗时 | 恢复额外内存 | 导出耗时 |
    |---|---|---|---|
    | 11 MB | 约 0.15 秒 | 约 20–34 MB | 约 0.3 秒 |
    | 20 MB | 约 0.2 秒 | 约 72 MB | 约 0.6 秒 |
    | 28 MB | 约 0.3 秒 | 约 88 MB | 约 0.8 秒 |

    结论：CPU 远低于 30 秒上限，限制在 128 MB 内存。备份建议 20 MB 以内。
  - 测试中顺手优化：上传带长度时不再在内存里多复制一份。
- **复制链接（3.5.2）**：HTTP 地址没有剪贴板接口时能复制；自动复制都被拒绝时弹出手动复制框并显示完整链接；首次分享在点击当下就开始写剪贴板；已分享的首页直接复制、不再请求服务器。
- **模拟 Durable Object 的限制**：测试用的存储替身执行 Cloudflare 的规则：禁止 BEGIN/SAVEPOINT 语句、每条 SQL 最多 100 个参数、单个值和整行最多 2 MB、BLOB 以 ArrayBuffer 返回。整套测试都在这些限制下通过。
- **打包检查**（`npm run verify:cf`）：用 esbuild 按 wrangler 的方式打包 `cf/index.js`，共 40 个文件、约 1.1 MB。运行时只依赖 `cloudflare:workers`、`node:crypto`、`node:zlib`、`node:async_hooks`，Docker 运行层没有被打包进去。打包后的代码可以正常运行健康检查、PWA 图标、首页、登录（带 Secure Cookie）、建合集、公开 `.rex`、Cron 和闹钟。
