# 3.5.7（2026-11-22）

以 3.5.6 为底。数据库结构、模块/合集/首页 ID、分享名、公开地址、备份格式都不变，直接覆盖部署即可，数据保留（`name` 不要改）。

## CF 修正了什么

1. **首页包上传报「首页 ZIP 解压失败或超过大小限制」**：Hub 原来用 Cloudflare 自带的 zlib 解压，Cloudflare 上的行为和本地 Node 不完全一样，部分 Rex 导出的正常首页包（例如 2.2 MB、128 KB 的包）在 CF 上传失败。现在改用 Hub 自带的解压程序（`inflate.js`），结果在任何环境都一致，解压大小上限由 Hub 自己控制。
2. **首页包被误判「内容校验失败」**：Rex 导出的包里常有校验值很大的文件，不再使用 Cloudflare 自带的校验函数，统一用 Hub 自己的算法。
3. **出错看不出原因**：解压失败时会附上出错的文件名和具体原因，方便截图排查。
4. CF 版不再依赖 `node:zlib`。

## 验证

- 自带解压和标准 zlib 用 800 组随机数据（各压缩级别、各策略）逐字节比对，全部一致；截断、损坏、超过上限都会报错，不会卡住。
- 用户反馈失败的 2.2 MB、128 KB 两个首页包：在单文件部署版（`single-file/index.js`）上传成功，导出与原文件逐字节一致。
- 全部测试：CF 263 项通过；本地 Node 264 项（263 通过、1 项因环境跳过）。两轮完整测试 + 工程检查：2 万组随机数据与 zlib 逐字节一致、2 万组损坏数据无异常无卡死、6 种变异测试都能被测试发现、3.5.6 的数据库直接升级到 3.5.7 数据完整。
- 仍未在真实 Cloudflare 账号上验证，部署后请先上传一次之前失败的首页包确认。

## CF 的限制（不变）

- 首页包单个最多 25 MiB；备份 20 MB 以内稳妥，超过 30 MB 基本不行（失败会整体回滚）；单次上传最多 100 MB。
- 订阅地址只能用公网地址；自动整理大约 5 分钟一次；免费计划每个 Hub 存储最多 1 GB（Cloudflare 免费计划每个 Durable Object 的上限）。
