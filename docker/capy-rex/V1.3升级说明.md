# V1.3 升级说明

V1.3 在原有数据模型、作者分组、用户权限和审核流程上增加搜索、统一界面、在线检查和 Capy 原文兼容入口。

## 使用入口

| 功能 | 现网地址 |
|---|---|
| 公开组件与搜索 | https://your-domain.example.com/user |
| 开发者 / 管理员 | https://your-domain.example.com/admin |
| 管理员模块台 | https://your-domain.example.com/admin/manage |
| 在线静态检查 | https://your-domain.example.com/checker |

公开搜索支持组件标题、文件名、作者、`capy` / `CapyPlayer` / `rex`；空格分词采用同时匹配。作者下拉框与播放器筛选可叠加，一键清除恢复全部。搜索在已返回的公开目录中完成，无额外服务或数据库迁移。

## 界面与安装

- Capy 是品牌、筛选、上传选择器、favicon 和 PWA 图标的第一优先级；Rex 保留独立图标，安装入口也显示 Rex 图标。
- 统一使用系统无衬线字体，明确包含苹方、微软雅黑、Noto Sans CJK。灰白表面、圆角与紧凑控件为主，颜色用于链接、焦点和提示。未引入远程字体、追踪服务或大型前端框架。
- 上传页与检查页显著显示“测试前请勿加密！”。Rex 明文先到官方测试页测试，通过后再加密投稿；加密后的内容无法在静态检查器中验证内部代码。
- 手机安装按钮使用 `com.feifeiduck.capyplayer://add-widget?data=<HTTPS地址的base64url>`。完整协议中 `:` 不可省略。
- Windows 点击 Capy 安装按钮会复制 HTTPS 原文地址。App 内“添加组件”的 URL 输入框只应粘贴 HTTPS 原始 JS 地址，不要粘贴 `com.feifeiduck...` 协议。该协议用于浏览器唤起 App。

## Capy 原文入口与故障排查

用户提供的 UUID `68ba435e-1f1d-47d6-b312-a5f2c62058e1` 正确。V1.3 使用同一 UUID：

```text
https://your-domain.example.com/raw/68ba435e-1f1d-47d6-b312-a5f2c62058e1.js
```

排查复现了原 `/api/modules/<UUID>.js` 的 CDN 压缩协商异常：请求仅接受 identity 或 gzip，缓存仍返回 `Content-Encoding: br`，且响应没有 `Vary`。正确解压后的源码与源站逐字节一致，无 BOM、无 UTF-8 替换字符，也不是 JSON 错误体。Acorn 与隔离环境内 JavaScriptCore GTK 2.50.6 的原生语法检查均通过；JavaScriptCore 对照环境不等同于用户 App 的版本和宿主沙箱。

新 `/raw/<UUID>.js` 沿用原存储文件，不改 UUID、源码、作者、版本、分类或归属；设置 `Cache-Control: no-store, no-transform` 和 `Vary: Accept-Encoding`。现网 9 种 UA / Accept / Accept-Encoding 组合均返回同一份 16,717 字节 UTF-8 源码，没有压缩或重定向。旧链接仍保留。

这解决了已复现的传输风险，**不能仅凭这些检查认定已经复现并修复 App 的 `unexpected token in expression '{' at eval1:1`**。实际 CapyPlayer App 内重新导入仍需用户验证；若仍出错，应保留 App 版本、平台和完整导入日志继续定位，不能再用 UUID 错误或 Windows 不支持解释该 JS 语法错误。

## 在线检查器：实际网页应用

Hub Docker 已在同一域名 `/checker` 提供页面、JS 和解析器，不需要新增 Lucky 规则或端口。浏览器选择文件或粘贴源码后，可查看语法错误行列、全局元数据声明、静态可见入口函数和兼容性提示。

采用现有开源 Acorn 解析器，不自行实现 JS 解析器。Rex 官方运行测试页 `https://modules.rexnow.app/` 已只读访问验证，可作为明文运行测试入口；未将第三方源码上传给该站。

边界与配额：

- 仅静态解析；不执行 `eval`、`new Function`、用户脚本或组件网络请求，也不使用 Node VM 运行上传代码。
- 文件与代码留在浏览器 Worker，不上传、不持久化。解析每次上限 512 KiB、3 秒、单任务；检查之间至少间隔一秒；退出页面终止 Worker。Hub 投稿文件上限仍为 2 MiB，二者独立。
- 页面与 Worker 的 CSP 限制为同源脚本，`connect-src 'none'` 禁止检查器发起网络请求。服务器只发送静态资源，不接受源码运行请求。
- 无法确认运行时返回值、网络可达性、解密真实性、代码安全性或 App 最终兼容性。动态生成字段显示人工核对提示。
- Hub 继续使用既有请求体、连接数和上传超时限制；检查器不会消耗服务端解析任务或额外常驻浏览器进程。

另提供真正可单独运行的 Docker 网页应用，`validator/Dockerfile` 默认已改为 HTTP 服务，不再默认启动 CLI：

```sh
docker build -t capy-rex-validator:V1.3 -f validator/Dockerfile .
docker run -d --name capy-rex-validator \
  --restart unless-stopped --read-only --cap-drop ALL \
  --security-opt no-new-privileges --pids-limit 32 \
  --memory 128m --memory-swap 128m --cpus .5 \
  -p 18887:8080 capy-rex-validator:V1.3
```

独立应用访问 `http://NAS地址:18887/checker`。不挂载主机目录、数据库、Docker socket 或凭据。服务仅 GET / HEAD，写请求 405；每 IP 每分钟 60 次、全局 300 次、最多 16 连接，超过配额 429 并提供 Retry-After。源码依旧只在访问者的浏览器中静态解析。现网已通过 Hub 提供服务，**不需要同时再部署这个容器**。独立容器的浏览器测试和 405 / 429 测试均已完成。

旧离线工具保留为 `validator/check.sh`，仅供已有 CLI 用户兼容；网页版是默认交付入口。

## 升级、备份与回退

保留已有 `.env` 和整个 `data/`，不要覆盖配置或运行初始化。新发行 ZIP 不包含这些文件。

```sh
docker exec capy-rex-hub-1 node nas/backup.mjs
docker compose build hub
docker compose up -d --no-deps hub
```

本次部署已保留旧镜像 `capy-rex:rollback-v12`，旧源码及 `.env` 私有快照位于 `/path/to/capy-rex-rollback-V1.2/source-private.tar.gz`（权限 600）。该私有归档不在交付 ZIP 中。

本次部署前 SQLite 一致性备份：

```text
/path/to/capy-rex/data/backups/nas-full-2026-11-27T05-29-55-621Z-129d0876.sqlite
```

V1.3 无数据库结构迁移。回退应用时，将现有 `compose.yaml` 中的 hub 镜像改为 `capy-rex:rollback-v12`，保留其余配置后执行 `docker compose up -d --no-build --no-deps hub`，同时恢复旧源码以防后续误构建。通常不需要还原数据库，以免覆盖升级后新投稿。若必须回退数据，先停止容器并另存当前数据库、WAL/SHM，再使用部署说明的完整备份恢复流程；不要在运行中直接覆盖 SQLite 文件。

本次未改 Lucky、Gateway、宿主机浏览器配置、生产账户或原组件源码。
