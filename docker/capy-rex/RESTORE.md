# 备份恢复：提速、进度与中断保护

## 使用

1. 设置 → 工具 → 恢复，选择 Hub 导出的 JSON 备份。
2. 核对文件名和提示，点击「确认恢复」。相同 ID 内容会被覆盖，不在备份内的其他数据沿用原有恢复行为保留；遇到身份、路径或来源冲突则中止。
3. 等待上传百分比、校验模块数量、写入模块数量，最后以「恢复完成」为准。进度按阶段计算，不是统一预计剩余时间；100% 写入不等于事务已经提交。
4. 上传完成后可以关闭弹窗，重新打开「恢复」可查询原任务。断线或请求超时后不会自动再上传一遍；先等状态确认。上传未完成时不要关闭或刷新页面。

浏览器保存任务编号，服务端在现有 `rex.sqlite` 中保存结果。服务重启不自动重放备份：未完成任务标记「中断」，未提交的写入由 SQLite 回滚；已提交的恢复和成功记录同时保留。没有断点续传，上传中断后须等失败/中断状态确认，再重新选择备份。

只允许管理员创建/上传/查询任务；同时只执行一个恢复。状态查询不受写入事务排队影响。关闭弹窗不是取消恢复，不应在任务进行中再次清空数据或发起其他管理操作。

## 兼容与安全

- 继续兼容 format 1–8；没有首页配置时仍导出 format 7，有首页时使用 format 8 保留原文件及分享身份。旧版本不能恢复 format 8，不能手改格式编号绕过检查，详见 [HOME-CONFIGS.md](HOME-CONFIGS.md)。
- 模块与上一版的原始字节、内容摘要以及图标会预先校验；身份、合集 slug、历史别名和订阅来源冲突仍在同一个发布事务内重新检查。
- 恢复仍是整体提交；校验或写入失败不会留下半份模块/合集/首页。成功状态与恢复数据在同一事务提交；首页分享身份冲突也会中止恢复。
- 不更改模块 ID、合集 ID、公开路由、内网权限或 HTTPS 证书规则。不在恢复过程中联网刷新上游。
- 新增任务状态表和只读查询连接，仍使用原数据卷，不新增挂载或环境变量。仅保留最近 100 条终态任务（启动时清理），任务状态不包含备份内容或登录凭据。

## 大小和时限

- 恢复 JSON 上传上限 512 MiB，总上传时限五分钟；单模块仍最多 25 MiB。普通请求体仍为 128 MiB、接收时限 30 秒。
- 此上限不是可承诺的低内存容量。服务端仍需持有 JSON 和解码后的文件，过大备份可能超出 NAS/容器内存；建议为大库使用一致性 SQLite 快照并按 `UPGRADE.md` 的离线恢复步骤操作。
- 反向代理可能设置更小的上传上限/更短超时。上传没有到达容器时，任务会等待上传超时后失败；不要盲目重复提交。
- 发布事务期间，其他管理/公开数据库请求可能等待；状态查询可以正常返回。没有引入公开资源缓存或取消原事务。

## API

这些接口均需有效的 `fwh_admin` 管理员会话，响应禁止缓存。

| 请求 | 行为 |
| --- | --- |
| `POST /api/admin/backup/restore/jobs`，JSON `{ "id": "客户端生成的 UUID" }` | 预留任务，首次返回 201；同 ID 返回已有状态，另有任务运行返回 409 |
| `PUT /api/admin/backup/restore/jobs/:id` | 请求体为原始备份 JSON，接收后返回 202；重复提交同任务不重复执行 |
| `GET /api/admin/backup/restore/jobs/:id` | 获取阶段、处理数量、结果或错误；不存在返回 404 |
| `GET /api/admin/backup/restore/jobs/current` | 当前运行任务，空闲为 `job:null` |
| `POST /api/admin/backup/restore` | 兼容原接口，仍等待最终结果，受同一个恢复锁约束 |

`status` 为 `uploading`、`validating`、`writing`、`done`、`failed` 或 `interrupted`；`stage` 另可为 `reading`、`waiting`、`validating_homes`、`writing_homes`。`processed/total` 只表示当前阶段的模块或首页数量。最终结果以 `done` 及 `result` 为准。

## 本机性能记录

2026-11-20，使用本机临时合成库、真实 HTTP、相同诊断脚本比较原路径与优化路径。135 个模块、33.8 MiB 原始字节/约 45.1 MiB JSON，恢复处理从约 1423 ms 降至约 295 ms；不包含真实 NAS、移动网络、反向代理或磁盘速度差异。4 MiB 单加密模块的旧正则栈溢出路径已修复，并验证恢复字节一致。

完整测试与边界见 `VALIDATION.md`。上述为功能开发阶段记录；本版已于 2026-11-21 部署 NAS 并推送 Docker Hub，未在生产库执行恢复测试。
