# 授权分析与修复

1. 界定要修复的模块/服务和可用输入：源码、公开文档、授权页面、脱敏请求或日志。先静态查看类型、结构和外部依赖，记录失败入口及期望输出；不执行上传 JS 来识别它。
2. 对相关页面采用观察→最小采样→重建→最小修改→复测。用实际可用的浏览器网络记录、脚本来源与 initiator 定位请求和参数生成链；MCP/CDP 只有宿主确实提供时才调用，不自动改客户端配置或假定工具存在。
3. 将请求方法、分页、编码、响应结构、必要公开头和参数变换整理成脱敏 fixture。授权签名或加密格式分析只在必要的来源与样本范围内进行，密钥通过宿主安全入口使用。对比实际响应再重建纯数据变换；缺样本时标明阻塞，不能用占位值冒充成功结果。
4. 按首次差异定位：请求 URL/参数→HTTP 状态→数据解码→DOM 选择器→映射字段→详情/播放。需要补运行环境时依据观测结果逐项添加；不要虚构 window、DOM 或 crypto 能力使测试假通过。
5. 保留原文件，修改最小必要逻辑后跑同一输入，再测错误路径和另一页。JS 混淆代码先静态解析 AST 与数据流；只有已审阅的自有/转换代码进入隔离环境，不使用 eval/new Function 运行未知输入。Node vm 不是安全隔离边界。
6. 交付复现条件、原因、改动、测试结果与仍未证明的假设。配置变更先读现状并保留回退；部署影响按用户已有授权范围处理。无需重复索要已给出的授权。

本工作台聚焦模块播放器工程：源码理解、协议/数据格式、接口适配、维护修复及部署验证。不加载与任务无关的游戏外挂、凭据攻击、批量扫描或模型规则覆盖模块。
