# 分层验收与 Docker / CF 发布

## 模块验收

| 层级 | 执行与证据 | 不能替代 |
|---|---|---|
| 静态 | 语法解析、元数据/函数映射、字段类型、依赖、敏感配置扫描 | 真实请求与播放器行为 |
| 隔离模拟 | 已审阅代码与合成 fixture；限制网络、CPU、时间；记录调用/参数/异常 | 真实 DOM、线上 API |
| 真实 HTTP | 授权输入的状态、字段、图片字节与解码 | 浏览器和 App |
| 浏览器 | 实际操作官方测试页/管理平台，检查网络和界面 | 原生页面、真实播放与缓存 |
| App | 实机导入、列表、详情、翻页、线路、播放及专属入口 | 其他客户端版本的行为 |

静态识别未知上传脚本，不 eval、不 require、不先运行校验器来读取元数据。若外部校验器内部执行 JS，必须审阅并仅用于已审阅的自有转换代码，在独立隔离环境运行。Node vm 不是恶意代码安全沙箱。

Capy mock 只暴露官方形状：HTTP ok/status/data，DOM parse/select/text/attr/remove；Rex 为 statusCode/data、tmdb 直接数据体、Widget.html.load。每入口测第 1/2 页、空结果、缺字段、详情、多线路、超时、HTTP 失败和不可解析 HTML，确认异常不被静默空数组掩盖。封面检查最终地址保留前缀，DOM 文档均释放。选择依赖真实渲染时另外做浏览器测试。

Rex 官方工具从 https://modules.rexnow.app/skill/ 获取，先读源码和其参数说明再运行；本包没有复制未审阅的运行器。官方测试页执行代码且可能代理联网，仅对已审阅模块操作。记录请求、分页、关键词和语言；不能将网页预览写成 App 实测。加密发布在明文验收之后，保留维护源码。

## 平台发布

1. 为 Docker、CF 分开生成发布目录；运行源码、在线数据、私有备份、上游归档留在发布包之外。保留已有交付物，版本化输出；只打包所需源码、锁文件、示例配置、迁移与 README。
2. 管理平台不能通过执行上传 JS 来探测元数据；静态解析，预览输出转义，避免把代码当 HTML。覆盖上传/列表/编辑/下载/删除/搜索、错误显示与权限边界中实际实现的流程；加解密入口如仅外链就按外链验收。
3. Docker 检查 compose 配置、构建、新库启动、旧库迁移、UID/权限与 volume，重启后核对内容。SQLite 使用一致性备份/停写或 backup API，考虑 WAL，比较表结构和关键记录；回退保留旧镜像和可恢复数据。不能把在线数据库/用户账号打进 ZIP。
4. CF 检查 build/dry-run、bindings 与变量、平台适配、存储迁移及限制；有授权后部署并检查实际路由和持久化。两个平台使用同一业务规则时分别验收，不由 Docker 成功推断 CF 成功。
5. 交付版本、文件清单、SHA-256、启动步骤、环境要求、升级/回退方式和测试结果。ZIP 不含绝对路径、.. 路径逃逸、宿主目录、凭据、私人域名或运行数据。换目录解压后检查相对链接及随包脚本。

## 技能包验收

运行宿主提供的 AgentSkills frontmatter 校验器（若提供 skill-creator，使用其 scripts/quick_validate.py）；主 SKILL.md 少于 10000 字符，引用全部存在。执行 `node scripts/capy-links.mjs self-test`。对 examples/activation-demo.md 做菜单和路由人工核对；这是规范场景检查，不是实际 LLM 会话回归。未安装/未重新加载宿主时不宣称关键词自动生效。
