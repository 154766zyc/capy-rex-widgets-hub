# REXENC 静态信封检查

使用 `node scripts/rexenc-inspect.mjs inspect ./authorized-module.js`。工具仅读取最多 4 MiB 的普通文件，验证三行标记/JSON/Base64，不执行 JS、不联网、不输出 header 中的 iv/kb 或密文。输出字节长度、SHA-256、格式和公开版本值；失败返回非零。摘要用于校验，不证明来源可信。

已在线核对加密页公开 encrypt.js：validateEnvelope 检查 REXENC、v=2、mkv=rex-1、alg=A256GCM、iv 解码 12 字节、kb 解码 60 字节及载荷大于 16 字节。静态 helper 对 Base64 采用规范化严格检查；它可能拒绝某些宽松解码器接受的非标准文本。末尾换行可容忍；额外正文行拒绝。

`kb` 不是可以直接当 AES 密钥使用的已知明文。长度看起来像某种封装不能证明布局，不能把 60 字节任意切片后声称成功。A256GCM 是认证加密，结构正确不证明认证通过；密文末尾是否为 tag、是否存在 AAD 或额外封装必须由实际规范证明。

若有公开合法密钥与明确解包算法，可在本地隔离处理并验证认证结果；没有则使用作者明文或用户授权的外部服务。读取公开脚本不等于服务端密钥已公开。外部服务处理需事先说明发送内容和目的地，不自动上传用户模块。

REXENC 的源码保护与封面 AES 是独立问题。未解密模块时只能报告信封事实，不能由文件名、体积或 Base64 形式推断源码功能。随包没有上传样本、样本密文或私有路径。
