## 1. 你需要准备什么

| 项目 | 说明 |
|---|---|
| 一台电脑 | Mac 或 Windows 都可以，只在部署和升级时用到 |
| Cloudflare 帐号 | 免费计划就可以；有多个帐号见第 7 节 |
| 部署包 | `Rex-Widgets-Hub-CF-3.6.0-CF部署版.zip` |
| Node.js | 部署工具 wrangler 需要它，只要装一次（第 3 节） |
| 网络 | 部署时电脑要能连上 Cloudflare 和 npm |

**为什么不能直接贴进 Cloudflare 网页编辑器？** Hub 用 SQLite 型 Durable Object 存数据（操作失败会整体回滚）。第一次部署时 Cloudflare 必须读取 `wrangler.toml` 里的 `[[migrations]]` 才能建立这个存储，网页编辑器做不到，所以要用 wrangler。

## 2. 认识部署包

解压后得到 `rex-widgets-hub-cf-3.6.0` 文件夹，**部署只用其中的 `single-file` 文件夹**：

```
rex-widgets-hub-cf-3.6.0/
├── single-file/          ← 部署只用这个文件夹
│   ├── index.js          整个 Hub 打包成的一个文件（约 1.1 MB）
│   ├── wrangler.toml     部署配置（Worker 名称、数据存储、定时任务）
│   └── package.json      部署工具说明
├── cf/  test/  tools/    源码和测试（部署用不到）
├── 图文指南 PDF
└── 各种 .md 说明
```

| 文件 | 要不要改 |
|---|---|
| `index.js` | 不要改，升级时整份换掉 |
| `wrangler.toml` | 通用配置，没有要填的编号；只有想换 Worker 名称时才改 `name` |
| `package.json` | 不用改 |

`wrangler.toml` 里最重要的一行：

```toml
name = "rex-widgets-hub"
```

它决定网址：`https://rex-widgets-hub.<你的子域名>.workers.dev`。

> ⚠️ **升级时不要改 `name`。** 名字一变，Cloudflare 会当成一个全新的 Worker，里面是空的（原来的数据还在原来的 Worker 里）。

## 3. 安装 Node.js（只要一次）

1. 打开 <https://nodejs.org>，下载 **LTS** 版本。
2. 双击安装包，一路「继续 / 下一步」装完。
3. 打开终端机（第 4 节），输入下面的命令，显示 22 或更新的版本号就可以：

```bash
node -v
```

## 4. 打开终端机，进入 single-file 文件夹

**Mac**

1. 按 `⌘ + 空格`，输入「终端」，打开「终端机」。
2. 输入 `cd` 加一个空格，先不要按回车。
3. 把 `single-file` 文件夹从访达拖进终端机窗口，路径会自动填上，再按回车。

**Windows**

1. 在文件管理器里打开 `single-file` 文件夹。
2. 点地址栏，删掉原来的内容，输入 `cmd`，按回车。会打开「命令提示符」，而且已经在这个文件夹里了。
3. 请用命令提示符（cmd），**不要用 PowerShell**，可以避开脚本限制。

**确认位置对了**：Mac 输入 `ls`，Windows 输入 `dir`，能看到 `index.js`、`package.json`、`wrangler.toml` 这 3 个文件就对了。后面所有命令都在这个窗口里输入。

## 5. 第一次部署（3 行命令）

```bash
npx wrangler login
npx wrangler deploy
npx wrangler secret put ADMIN_PASSWORD
```

**第 1 行：登录 Cloudflare**

- 第一次运行问 `Ok to proceed? (y)`，按 `y` 再按回车。
- 浏览器会打开授权页面：登录你要部署的那个帐号，点 **Allow（允许）**。
- 终端机显示 `Successfully logged in` 就好了。

**第 2 行：部署**，大约 10–30 秒后大致会看到：

```
Your Worker has access to the following bindings:
  env.HUB (RexHub)            Durable Object
Uploaded rex-widgets-hub (… sec)
Deployed rex-widgets-hub triggers (… sec)
  https://rex-widgets-hub.<你的子域名>.workers.dev
  schedule: */5 * * * *
```

- 最后那个 `https://…workers.dev` 就是你的 Hub 网址，记下来。
- `schedule: */5 * * * *` 是每 5 分钟一次的定时任务（订阅检查、自动分类、清理）。
- 帐号第一次用 Workers 时，会请你先注册一个 workers.dev 子域名，按提示输入即可（英文字母、数字、连字符）。

**第 3 行：设置管理员密码**

- 出现 `Enter a secret value:` 时输入密码，按回车。**输入时屏幕上不显示字符是正常的。**
- 看到 `Success! Uploaded secret ADMIN_PASSWORD` 就好了。建议至少 8 位。

完成后，浏览器打开网址，用密码登录，再按第 9 节检查一遍。

## 6. 从旧的 3.5.0 升级

旧的 3.5.0 把数据存在 KV + D1 里，新版存在 Durable Object 里，**数据不会自动搬过来**。

**情况 A：旧站是空的（只有登录，没有模块）→ 直接覆盖**

1. 到 Cloudflare 网页 → Workers 和 Pages，看旧 Worker 的名字。
2. 确认 `wrangler.toml` 的 `name` 和旧 Worker 名字完全一样（默认 `rex-widgets-hub`）。
3. 执行第 5 节的 `npx wrangler login` 和 `npx wrangler deploy`。
4. 网址不变；旧 Worker 设过的 `ADMIN_PASSWORD` 会保留，`secret put` 可以跳过。
5. 确认没问题后，旧的 KV 和 D1 可以在 Cloudflare「存储和数据库」里删掉。

> ⚠️ 如果在 3.5.0 管理页里改过密码，新版不会沿用（它存在旧的 D1 里）。请用 `ADMIN_PASSWORD` 机密的值登录，或重新 `npx wrangler secret put ADMIN_PASSWORD`。

**情况 B：旧站有数据 → 新建再迁移**

1. 把 `name` 改成新名字，例如 `rex-widgets-hub-357`。
2. 执行第 5 节的 3 行命令。
3. 按第 8 节把数据迁移过来。
4. 新站确认正常后，再删除旧站。

## 7. 多个 Cloudflare 帐号

每个帐号一个文件夹，各自保留自己的 `wrangler.toml`；再用 Wrangler 的「帐号档案」把文件夹和帐号绑定，进哪个文件夹就自动用哪个帐号，**不用 logout / login 来回切换**。

**① 准备文件夹（只做一次）**

把 `single-file` 复制成两份，例如：

```text
D:\Rex\hub-A\   ← 帐号 A：index.js、package.json、wrangler.toml
D:\Rex\hub-B\   ← 帐号 B：index.js、package.json、wrangler.toml
```

两份 `wrangler.toml` 的 `name` 要和各自帐号上已有的 Worker 名字一致（都叫 `rex-widgets-hub` 也可以，帐号不同互不影响）。

**② 给每个帐号建档案并绑定文件夹（只做一次）**

```bash
cd D:\Rex\hub-A
npx wrangler@latest auth create hub-a      # 浏览器里登录帐号 A，选帐号 A
npx wrangler@latest auth activate hub-a    # 把当前文件夹绑定到 hub-a

cd D:\Rex\hub-B
npx wrangler@latest auth create hub-b      # 浏览器里登录帐号 B，选帐号 B
npx wrangler@latest auth activate hub-b

npx wrangler@latest auth list              # 看两个档案和绑定的文件夹
```

- 登录帐号 B 前，浏览器如果还记着帐号 A，先在 Cloudflare 网页上退出，或用无痕窗口登录。
- 第一次部署的帐号，还要在那个文件夹里执行一次 `npx wrangler secret put ADMIN_PASSWORD`。

**③ 以后部署**

进入哪个文件夹，就部署到哪个帐号：

```bash
cd D:\Rex\hub-A
npx wrangler@latest deploy

cd D:\Rex\hub-B
npx wrangler@latest deploy
```

**注意**

- 「帐号档案」是 Wrangler 2026 年 7 月新增的功能，官方标为测试版，命令以后可能会变；请用最新版（`npx wrangler@latest`）。
- 如果电脑设置了环境变量 `CLOUDFLARE_API_TOKEN`，它会盖过所有档案，请先删掉。
- 登录过期时，重新执行同名的 `auth create`（例如 `npx wrangler@latest auth create hub-a`）就好，绑定不用重做。
- 每个帐号的网址、数据、密码互相独立。

依次更新两个帐号的详细步骤见《图文指南》PDF 的第二部分。

## 8. 从有数据的旧站迁移

1. **旧站**：登录 → 设置 → **导出备份**，范围选「全部」，把 JSON 文件存好。
2. **新站**：登录 → 设置 → **恢复备份**，选择刚才的文件。支持 format 1–8。
3. 恢复方式默认「增量合并」（保留新站已有数据）；想让新站和备份完全一样，选「全量恢复」。恢复失败会整体回滚，现有数据不受影响。
4. 备份超过 100 MB 传不上来：在旧站「导出备份」里分开导出「模块数据」「首页配置」「文件栏目」，到新站分别恢复。
5. 恢复后，模块 ID、合集、首页、分享名、公开地址都和旧站一样，只是域名换了：
   - 有自定义域名：在 Cloudflare 把域名从旧 Worker 移到新 Worker，Rex 里不用改。
   - 没有自定义域名：把 Rex 订阅地址里的 `xxx.workers.dev` 换成新网址。

## 10. 以后怎么升级（含 3.5.8 → 3.6.0）

1. 升级前在管理页「设置 → 备份」导出一份。
2. 用新的 `index.js` 覆盖部署文件夹里的旧文件；`wrangler.toml` 保留你自己那份，**Worker 名字不能变**。
3. 进入部署文件夹（第 4 节），执行：

```bash
npx wrangler@latest deploy
```

4. 多个帐号的话（第 7 节），把新的 `index.js` 分别覆盖到每个帐号的文件夹，每个文件夹各 `deploy` 一次，不用切换登录。
5. 数据、密码、网址都会保留；新增的数据库栏位第一次打开时自动补上。

**确认换成功**：用记事本打开 `index.js`，第一行是：

```
// Rex Widgets Hub 3.6.0 · Cloudflare 单文件版（由 cf/index.js 打包生成，不要手动修改）
```

**3.5.8 → 3.6.0 重点**

- 覆盖 `index.js` 再 `deploy` 即可。
- `wrangler.toml` 保留你自己那份；Cron 每 5 分钟不用改（3.6.0 每次维护只读几十行）。
- 第一次打开自动补 3 个索引，其它不变，数据保留。
- 已实测：3.5.8 的数据库用 3.6.0 打开，模块、合集、订阅完整，索引补上。
- 3.5.9（HTML 卡片版）也可以直接覆盖。
- 更早的 3.5.6 / 3.5.7 也可以直接覆盖（会同时新增「文件」表）。

想打开可选的**边缘缓存**才需要改 `wrangler.toml`，见第 17 节；不打开就什么都不用改。

## 11. 首页配置怎么用

「首页配置」用来保存和分享 Rex 导出的 `.rex` 首页包，原文件完整保留，不会展开导入模块。

1. 底部「合集」→ 顶部切到 **首页配置**。
2. 点右上角 **＋ 上传首页**，选择 Rex 导出的 `.rex`（最多 25 MiB），点「上传保存」。
3. 上传后自动读出名称、头像和栏目数量；点「导出 .rex」下载原文件。
4. 点右边的调整按钮：复制分享链接、替换文件、重命名、删除。

**给别人用**：把分享链接发给对方，对方下载 `.rex` 后用 Rex 打开，或在 Rex 里「导入配置」。Rex 官方目前没有「一键导入首页」的链接，所以首页配置没有「导入 Rex」按钮（模块和合集才有）。

**上传提示「首页 ZIP 解压失败或超过大小限制」？** 这是 3.5.6 及更早版本在 Cloudflare 上的问题，3.5.7 起已修好。如果还出错，提示后面会附上出错的文件名和原因，截图即可排查。

**Forward 的 `.fwd` 也能传**（3.5.8）：上传时自动转成 `.rex` 保存，栏目原样保留。转换结果还没在 Rex 里实测，导入后请检查一遍。

## 12. 忘记密码

```bash
npx wrangler secret put ADMIN_PASSWORD
```

1. 输入一个新密码，按回车。
2. 用新密码登录。登录成功后它就是管理员密码，所有旧的登录会话都会退出。
3. 只有机密真的换过才会生效，旧的机密不会因此重新可用。

## 13. 常见问题与排错

| 症状 | 原因 | 解决 |
|---|---|---|
| 上传首页提示「首页 ZIP 解压失败或超过大小限制」 | 3.5.6 及更早版本在 Cloudflare 上解压有问题 | 升级到最新版（第 10 节） |
| `node` 或 `npx`：找不到命令 | Node.js 没装好，或装完没重开终端机 | 重装 Node.js LTS，关掉终端机再打开 |
| Windows：「无法加载文件 npx.ps1，因为在此系统上禁止运行脚本」 | 用了 PowerShell | 改用命令提示符（地址栏输入 `cmd`） |
| `Missing entry-point` 或找不到 wrangler.toml | 终端机不在 `single-file` 里 | 按第 4 节重新进入，用 `ls` / `dir` 确认 |
| 登录后浏览器报错，或终端机一直等待 | 浏览器拦截了授权页面 | 换一个浏览器，或复制终端机显示的网址手动打开 |
| 部署到了错误的帐号 | 文件夹没绑定帐号档案，或设了 `CLOUDFLARE_API_TOKEN` | 在该文件夹执行 `npx wrangler@latest auth list` 看绑定；没绑定就 `auth activate`（第 7 节） |
| 提示要注册 workers.dev 子域名 | 帐号第一次用 Workers | 按提示输入一个子域名 |
| 与迁移（migration）有关的报错 | 同名的旧 Worker 用了另一种 Durable Object 设置 | 换一个新的 `name` 部署（第 6 节情况 B），或在网页上删掉旧 Worker 后再部署 |
| `/healthz` 显示的不是 3.6.0 | 部署到了另一个 Worker 名称，或浏览器缓存 | 核对 `name`；无痕窗口再打开；检查 `index.js` 第一行 |
| 登录提示「密码错误」 | 用了 3.5.0 管理页里改过的旧密码 | 用 `ADMIN_PASSWORD` 机密的值，或按第 12 节重置 |
| 登录提示「尝试次数过多」 | 连续输错密码 | 等 5 分钟再试 |
| 恢复大备份失败 | 超过 100 MB 上传上限，或首页 / 文件内容太多占满内存 | 失败会整体回滚；在「导出备份」里分开导出模块数据、首页、文件，再分别恢复 |
| 恢复后多出了旧数据 | 用了默认的「增量合并」 | 想和备份完全一样，恢复时选「全量恢复」 |

## 14. 修正了 CF 什么

**3.6.0：省 Cloudflare 用量（重点）**

- **起因**：3.5.8 每 5 分钟的维护整表扫描；某站一次约 18,099 行，一天约 520 万行，超过免费 500 万。
- **维护走索引**：只读到期的那几行；1000 个模块一次约 5,035 → 约 35 行（3000 个约 47 行）。
- **内存缓存**：合集和管理页模块 / 合集 / 分组列表，没改数据时 0 次查询；304、HEAD 也是；管理列表要登录。
- **删 0 行不算写入**：维护不再把内存缓存清空。
- **自动分类**：没有新模块就跳过；图标清理最多 6 小时一次。
- **少写闹钟**：Cron 不再每 5 分钟重设；空闲最长睡 1 小时。
- **存储清理**：每张表只扫一遍。
- **静态文件**：图标、favicon、manifest、CORS 预检不进 Durable Object。
- **自动更新间隔、可选边缘缓存**：用法见第 17 节。
- **修正**：升级上来的站第一次打开也会补上新索引。

**3.6.0：HTML 首页卡片（重点）**

- **HTML 首页卡片（适配 Rex 1.2）**：首页包 version 2、`rex-html/`、内联 `htmlTemplate` 都能上传；包内文件数 32 → 256。
- **检查首页**：卡片、尺寸声明、缺字段、本机模块、外站链接、模块对照一次看清；首页卡片上直接显示摘要。
- **首页工具**：换成 Hub 模块链接、装上 HTML 卡片（另存或覆盖）、取消分享 / 换新分享链接。
- **真实数据实测**：Rex 1.2.1 备份里 35 个首页、8 张 HTML 卡片全部能上传、没有误报。
- **修正**：检查用线性扫描（10 MB 恶意 HTML 约 1.7 秒 → 约 70 毫秒）；大请求体只给上传首页、替换文件、装 HTML 卡片。

**3.5.8：新功能和省内存**

1. **恢复备份内存**：原来要把整份备份文本、解析后的对象、解码后的全部模块文件同时放进 128 MB 内存。现在边读边处理，模块文件读完一个就暂存一个，存活内存峰值降到原来的约四分之一（本地模拟：60 MB 备份约 105 MB → 约 23 MB）。
2. **订阅同步请求数**：每轮从 2 个模块提高到 6 个，同时下载仍是 2 个；Durable Object 请求次数约为原来的三分之一，同步更快。
3. **只同步失败**、**全量 / 增量恢复**、**部分导出**、**存储用量**、**文件栏目**、**图标上传**、**zip 上传**、**`.fwd` 转换**、**替换时填版本号**、**加密模块自动版本号**：用法见第 17 节。
4. 链接模块自动刷新到加密模块时不再清空作者；「清除所有数据」也会清空首页和文件栏目。

**3.5.7：首页包上传**

1. **上传首页包报「首页 ZIP 解压失败或超过大小限制」**：Hub 原来用 Cloudflare 自带的 zlib 解压，Cloudflare 上的行为和本地不完全一样，正常的 Rex 导出包也传不上去。现在改用 Hub 自带的解压程序（`inflate.js`），任何环境结果一致，解压大小上限由 Hub 自己控制。
2. **首页包被误判「内容校验失败」**：Rex 导出包里常有校验值很大的文件，现在不用 Cloudflare 自带的校验函数，统一用 Hub 自己的算法。
3. **出错看不出原因**：解压失败会附上出错的文件名和具体原因。
4. **不再依赖 `node:zlib`**。

**3.5.6：热点路径与内存**

- Rex 拉订阅 `.rex` 只查这个合集里的模块并加了索引；内容没变时回 304。
- 管理列表处理分享别名改为线性，输出不变。
- 导出备份改成边编码边输出，峰值内存约减半，输出逐字节相同。
- 图标回 304 或 HEAD 时不再读出整张图片。

**3.5.5：条件请求**

- 合集订阅和链接模块自动刷新会记住上游的 ETag / Last-Modified，上游没变就回 304，不下载、不写入。
- 「全部同步」时每秒那次只推进同步队列，完整维护每分钟最多一次。

**3.5.4：代码审查后的修复**

- 链接模块自动刷新不会再被坏源卡死；内容没变时不重写（Rex 不会重复下载）。
- 直链 `/<模块ID>.js` 支持 304。
- 改 `ADMIN_PASSWORD` 机密后可以重置密码，旧会话全部退出。
- 旧恢复接口收到坏 JSON 回 400 并给出提示；选择超过 20 MB 的备份时会提醒。
- 自动分类规则匹配改为预先分组，结果不变。

## 15. CF 的限制

| 限制 | 说明 |
|---|---|
| 单次上传最大 100 MB | Cloudflare 免费版和 Pro 版的限制，超过 100 MB 的备份传不上来（可分开导出：模块数据 / 首页 / 文件） |
| 首页包单个最多 25 MiB | 超过 256 KB 的内容自动分片存储，读出来是原文件 |
| 内存 128 MB | 3.5.8 起恢复备份边读边处理，模块文件一次只占一个；但首页配置和文件栏目的内容仍要整段读进内存，它们很多时请分开导出、分别恢复。导出是流式的 |
| 单次请求 CPU 默认 30 秒 | 免费计划的限制；付费计划可打开 `wrangler.toml` 里的 `[limits] cpu_ms`；实测 28 MB 备份恢复约 0.3 秒 |
| 单行 2 MB 上限 | 超过 256 KB 的文件自动分片存储，不影响使用 |
| 并发上限按请求数（64） | 不按内存计算，同时多个大上传仍可能把内存撑满 |
| 不能访问内网来源 | 订阅和链接只能用公网 HTTPS 地址 |
| 条件请求要上游支持 | 上游不给 ETag / Last-Modified 时，退回完整下载加内容比对 |
| 定时任务每 5 分钟一次 | 过期清理、自动分类、订阅检查、链接模块刷新都按这个节奏；3.6.0 起每次只读几十行；订阅和链接模块按设置的间隔（默认 6 小时）检查 |
| Durable Object 免费额度 | 每天读 500 万行、写 10 万行（`setAlarm` 和删除都算写入）。3.6.0 的定时维护一天约 1～1.5 万行（3000 个模块以内）；主要用量变成 Rex 拉合集（约 2 × 合集模块数 行）和管理页打开模块列表（约 2 × 模块数 行），都只在 Durable Object 被回收或改过数据后的第一次。实际用量看 Cloudflare 网页 → Durable Objects → 指标 |
| 内存缓存 | 只在 Durable Object 没被回收时有效；改了任何数据都会失效（保证内容最新） |
| 边缘缓存（可选，默认关） | 仍算 Worker 请求（免费每天 10 万次）；合集最多晚约 1 分钟、模块最多晚约 5 分钟更新；没在真实 Cloudflare 上测过 |
| 同步速度 | 每轮 6 个模块（同时下载 2 个），比 3.5.7 快约 2～3 倍，实际看上游下载速度 |
| 文件栏目 | 只收 PDF、txt（UTF-8）、zip；单个 25 MiB，总共 100 MiB、200 个 |
| 图标上传 | PNG / JPEG / WebP，单张 2 MiB；图标缓存总共 128 MiB |
| `.fwd` 转换 | 栏目原样保留；头像只保留 PNG；转换结果没在 Rex 实测 |
| 存储空间：免费计划每个 Hub 最多 1 GB | Hub 的数据都在一个 Durable Object 里，Cloudflare 免费计划每个 Durable Object 上限 1 GB（付费计划 10 GB）；满了以后写入会失败，读取不受影响；设置页「存储用量」可以看已用多少 |
| 首页包没有「导入 Rex」按钮 | Rex 新版已支持用链接导入首页，Hub 还没接上；目前下载后用 Rex 打开 |
| 未经真机验证 | 以上数据来自本地模拟的 Durable Object，没有在真实 Cloudflare 帐号上验证过；部署后请按第 9 节检查 |

## 17. 3.5.8 / 3.6.0 新功能怎么用

### 3.6.0：自动更新间隔

设置 →「自动更新」→ 选 6 / 12 / 18 / 24 小时（默认 6 小时），选完自动保存。

- 对合集订阅和链接模块都有效，下一次按「上次完成时间 + 新间隔」重排。
- 间隔越长，越省 Cloudflare 额度和上游流量。
- 手动「同步」「全部同步」不受影响。

### 3.6.0：边缘缓存（可选，默认关闭）

- **作用**：Rex 拉合集（`.rex`）和下载模块由 Cloudflare 边缘缓存直接回，不进 Durable Object、不读数据库行。
- **仍算**：一次 Worker 请求（免费每天 10 万次）。
- **代价**：合集最多晚约 1 分钟、模块最多晚约 5 分钟更新（和 Rex 自己的缓存时间一样）。
- **安全**：管理页、登录等带 Cookie 的请求永远不进缓存。
- **注意**：没在真实 Cloudflare 帐号上测过；一般用不到，Durable Object 请求接近每天 10 万次时再考虑。

打开方法：

1. 把 `wrangler.toml` 里的 `compatibility_flags` 改成 `["nodejs_compat", "enable_ctx_exports"]`。
2. 在 `wrangler.toml` 最后加上下面几行（新包的 `wrangler.toml` 末尾已经写好，去掉 `#` 即可）：

```toml
[cache]
enabled = true
[exports.default]
type = "worker"
cache = { enabled = false }
[vars]
EDGE_CACHE = "1"
```

3. 重新部署：`npx wrangler@latest deploy`。打开合集 `.rex` 地址，第二次刷新时响应头 `cf-cache-status` 应是 `HIT`。

关闭：把这几行重新加上 `#`（或删掉），再 `deploy` 一次。

### 3.6.0：HTML 首页卡片和首页工具

- **检查首页**：合集 → 首页配置 → 首页的调整按钮 →「检查首页」；只读，不执行脚本、不联网；可复制全文。
- **报告内容**：HTML 卡片（来源、模板 ID 和版本、几行共用、字节数、尺寸声明）、缺字段、本机模块、外站链接、模块对照。
- **换成 Hub 模块链接**：调整按钮 →「换成 Hub 模块链接」；本机模块 / 内置脚本换成本站同 widgetId 的链接。
- **装上 HTML 卡片**：调整按钮 →「装上 HTML 卡片」；选项目、上传官方单卡 `.html`，自动配好 `style` / `gridSize`，manifest 改成 2。
- **保存方式**：另存为新首页（默认）或覆盖当前首页（保留 ID 和分享链接）。
- **分享**：已分享的首页可以「取消分享」或「换新分享链接」。
- **限制**：检查是静态的，不代表 Rex 里一定能显示；单张 HTML 最多 32,768 字节；生成的首页包没在 Rex 真机导入过。

### 3.5.8 新功能
